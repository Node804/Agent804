# Agent804 0.6.0 public preview

Prepared for the next public preview after 0.4.0. Publication is pending; this file is the
release-note draft. The 0.5 development work is included in 0.6, not a separate published release.

## What changed since 0.4

- Four cumulative levels: Guided, Controlled, Verified and Sustained. The 38 core gate IDs
  remain, grouped into named practices. Partial/missing gates block advancement; unresolved
  facts support only a separately labeled provisional level. Targets and additional prototype
  requirements are explicit. Old scores must be reassessed rather than relabeled.
- Guided adoption for existing code: one bounded improvement, reuse of working tools,
  failure-aware checks/style setup, evidence and a resumable next increment. Assessment stays
  read-only and recommends one next action with at most two optional follow-ups.
- Current behavior has a maintained home, reusing README/contract guides where possible.
  Proposed deltas stay in specs/plans; verified delivery reconciles the current description.
  Historical specs, Accepted decisions and dated evidence retain their separate roles.
- Requirements and interaction discovery now distinguishes facts, assumptions and agreed
  choices. The new Trial plan skill maps dependent work to verifiable increments and
  combined checks. Small changes keep short criteria without extra planning artifacts.
- Tighter assess/start/adopt/spec instructions and scoped loading. The check now reports
  skill sizes and explicit workflow read recipes, with per-file/selector JSON details through
  `python scripts/context_load.py --host codex --json`. Estimates do not measure live usage.
- Completion evidence is core GR-4; automatic completion integration is optional Trial GR-8.

## Removed completion integrations

No Stop adapter or enabling recipe ships in 0.6. Codex Desktop did not automatically continue,
and attempted remedies did not enable it. The shared Claude/Grok engine had known dirty-gitlink
cache, EOF-input and unbounded-child limitations. All supplied runtimes and adapter fixtures
are withdrawn; action-permission settings, direct checks, CI guidance and historical evidence
remain. This is withdrawal, not a claim that host/runtime defects were fixed.

## Updating from 0.4

1. Replace the installed kit folder with the intact new release; remove old kit files first
   so deleted adapters do not linger. Preserve your project-owned work and configuration.
2. Separately review any Stop handlers already copied into projects. Updating the kit does
   not uninstall them. Change only the reviewed Agent804 handler/configuration within your
   authorized scope; preserve unrelated hooks, diagnostics, trust and stricter action controls.
3. Run your project's check directly and retain current commands, scope and results. Required
   CI and human review remain. Reassess earlier hook-based GR-4 findings under the new rule;
   missing hooks alone no longer block core, but absent/failed verification still does.
4. Reassess earlier foundation/coverage scores using the new levels. Do not convert labels.
   Refer to the developer guide for incremental adoption; no wholesale project migration is needed.

## Evidence and limits

Kit tests establish consistency, scoring regressions, resource layout and modeled context
calculations. Fresh review and package verification are recorded in the release preparation
plan. Neither demonstrates real-project effectiveness, deployment, live context savings or
host enforcement. Discovery/planning and current-behavior trials, revised scoring reassessment
and complete adoption/host workflows remain pending. This is a preview whose rules can change.

The local candidate is a verified working-tree snapshot. Publication requires an authorized
release commit and a final archive rebuilt from that commit; no release is published by these notes.
