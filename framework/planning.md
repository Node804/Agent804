# From a request to verifiable work

Agents can turn an unstated assumption into implementation before anyone notices the missing
decision. Tests written independently can still confirm the wrong requirement. Discovery
supports TS-1 and TS-6 by exposing the gap before it becomes agreed behaviour.

Agent804's `spec` skill therefore connects the current problem, affected users and constraints
to observable outcomes. Existing code and records supply facts; the developer supplies choices
that those facts cannot settle. The size of the uncertainty matters as well as code size.
A focused regression can be enough for a small fix, while a new workflow needs its exceptions
and refusal paths understood.

## Experience is observable behaviour

A screen description that covers only success leaves agents to invent errors, recovery and
permission boundaries. Relevant interaction states and accessibility needs belong in criteria
because a user experiences them as behaviour. Existing design conventions reduce unnecessary
choices. Sketches can help settle a choice, but their existence proves neither agreement nor
working software. Broad product discovery and specialist design methods can feed this process;
the developer retains responsibility for what is worth building.

## Increments keep the whole visible

The Trial `plan` skill extends WK-2 for work spanning several changes. Stable increment IDs
and criterion mappings help later sessions see omissions and avoid building unrelated work.
A thin complete journey tests assumptions across boundaries earlier than a set of disconnected
layers. Infrastructure prerequisites still have a place when their consumers and verification
are explicit.

Individually passing changes can disagree at their shared contracts. Dependency ordering,
integration checkpoints and combined-result evidence protect the whole outcome; concurrent
writers also need WK-6 isolation. Progress records distinguish partial delivery from completion
and preserve the revision to which each result belongs (GR-4).

## Adoption and limits

These are workflow extensions to existing rules, with no new core gate, level or scored module.
The spec and plan are the normal artifacts; an existing tracker can hold equivalent records.
Small changes incur no extra planning document. Staffing, organizational sign-off and release
governance remain the developer's process. Plans do not grant action authorization (GR-7).

The 0.6 discovery, interaction and increment guidance is untrialled. Kit integrity checks cannot
show that agents ask useful questions or produce deliverable slices. Real-project trials must
record missing assumptions, corrections, integration failures and the overhead of the records
before stronger effectiveness claims or additional requirements are justified.
