# Discovery and increment planning (0.6)

The developer requested implementation of the bounded expansion discussed after comparing
Agent804 with BMAD: stronger requirements discovery, relevant interaction outcomes, work
slicing and limited delivery coordination. This is a local workflow design, not evidence
that one framework is more effective than another. No external reference is added here.

`spec` now distinguishes existing facts, proposed assumptions and agreed choices, examines
relevant user journeys and reuses answers already supplied. The new Trial `plan` skill maps
agreed criteria to verifiable increments, dependencies, integration checkpoints and resumable
handoffs. Existing TS-1, TS-6, WK-2, WK-6 and approval boundaries apply; no rule, gate or module
trigger changes. An optional experience-design module remains a future possibility, not a
new requirement in 0.6.

## Verification boundary

Kit checks validate portable metadata, paths, rule citations, budgets and document integrity.
Skill validation checks frontmatter and naming. Neither proves discovery quality, usable
interaction design, dependency correctness, agent execution or lower delivery overhead.
No live project, release, worker orchestration or model-comparison trial is claimed.

Pending real-project scenarios: a clear small fix with no extra artifact; a larger ambiguous
request with consequential assumptions resolved by the developer; an interaction with failure,
refusal and recovery; several dependent increments with combined verification; and a scope
change or blocked prerequisite recovered in a later session. Record missed requirements,
developer corrections, actual red/green evidence, integration defects and record overhead.
